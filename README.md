## 🚀 快速开始

**目标：下载项目 → 安装依赖 → 填写密钥 → 打开页面 → 完成第一次筛选。**

> 已经安装并配置过？直接打开 `D:\Resume-Assistant`，双击 `Start.cmd`，再访问 [工作台](http://127.0.0.1:8000/ui/)。首次使用请按下面的步骤操作。

### ① 准备好两样东西

- **Python 3.12**：安装时勾选“Add Python to PATH”，在 PowerShell 输入 `python --version` 确认可以使用。
- **智谱 API Key**：账号需可调用 `glm-5.3-flash` 和 `embedding-3`，且有可用额度。这两个模型按调用用量计费。

当前默认使用本地 ChromaDB，无需另外安装数据库服务，也无需单独安装前端依赖。

### ② 下载并安装

安装了 Git 的用户，在 PowerShell 依次执行：

```powershell
cd D:\
git clone https://github.com/PUREGIT1028/Resume-Assistant.git
cd D:\Resume-Assistant
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-local.txt
Copy-Item .env.example .env
```

没有 Git？在仓库页面点击 **Code → Download ZIP**，解压并将包含 `README.md`、`app` 和 `Start.cmd` 的项目根目录命名为 `D:\Resume-Assistant`。在该目录打开 PowerShell，从上面 `python -m venv .venv` 这一行开始执行。

> 依赖安装耗时取决于网络，等待安装完成再继续。已有 `.env` 时不要再次复制覆盖，直接编辑现有文件。

### ③ 填写自己的密钥

在项目目录执行：

```powershell
notepad .env
```

找到下面两行，将占位内容替换为自己的智谱 API Key，然后保存文件：

```dotenv
LLM_API_KEY=你的智谱APIKey
EMBEDDING_API_KEY=你的智谱APIKey
```

同一把密钥具备两个模型权限时，可以在两处填写相同的值。其余参数先保留模板默认值，即 `glm-5.3-flash` + `embedding-3`。不要将填写后的 `.env` 上传 GitHub。

### ④ 启动并打开页面

仍在 `D:\Resume-Assistant` 下执行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn local_app:app --host 127.0.0.1 --port 8000
```

看到服务启动成功后，打开 **[http://127.0.0.1:8000/ui/](http://127.0.0.1:8000/ui/)**。

使用这条命令启动时请保留 PowerShell 窗口，关闭窗口会停止服务；按 `Ctrl+C` 可以主动停止。以后也可以在项目目录双击 `Start.cmd` 启动，使用 `Stop.cmd` 停止。

### ⑤ 完成第一次筛选

1. 在网页选择 `sample_resumes/demo_ai_product.md` 和 `sample_resumes/demo_backend.md`，点击上传并等待解析完成。这两份是虚构演示简历。
2. 在岗位需求框输入：

   > 寻找 AI 产品方向候选人，了解 RAG、Python 和需求分析，有相关项目经验优先。

3. 点击 **开始智能筛选**，等待后台进度完成。
4. 查看候选人排序、技能标签、待核实条件及详细分析。模型报告失败时，系统会提供明确标注的本地规则分析。

**页面能打开、示例上传成功、筛选结果可查看，就完成首次使用。** 上传和筛选会调用模型，请勿连续重复提交；历史记录可直接查看已有结果。

### 遇到问题先看这里

| 现象 | 优先检查 |
| --- | --- |
| `python` 命令无法识别 | 是否安装 Python 并添加到 PATH，安装后重新打开 PowerShell |
| 依赖安装失败 | 网络是否正常、当前是否位于项目根目录，以及 Python 是否为建议版本 |
| 页面提示“拒绝连接” | 启动命令是否仍在运行，访问端口是否为 `8000` |
| 模型鉴权失败或额度不足 | `.env` 中两处密钥、账号模型权限、余额及网络连接 |
| 上传后没有提取到文字 | 改用文字版 PDF 或 UTF-8 编码的 TXT / MD；当前未集成扫描件 OCR |

接口文档：[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。更多参数见 [`.env.example`](.env.example)，更多操作见 [本地使用说明](本地使用说明.md)。

**运行范围：Windows、本机单进程。** PDF 文字重建版使用 Windows 中文字体；其他操作系统需要调整字体路径并重新验证。

## 💡 项目介绍

拾才是一款面向招聘初筛场景的本地 Web 应用。用户上传简历后，可以用自然语言描述岗位需求；系统结合大模型解析、语义检索、条件对照与多维评分，生成候选人排序和匹配分析，辅助人工复核。

例如：

> 寻找一位有 3 年以上经验的 Python 后端工程师，熟悉 FastAPI 和 SQL，本科及以上，可在北京工作。有 Docker 实践经验优先。

本项目基于 [LLM-Agent-Resume](https://github.com/liangdabiao/LLM-Agent-Resume) 二次开发，在原有筛选流程上，完善了工作台界面、数据持久化、后台任务、历史记录、简历原件管理和回收站等功能。

**项目定制与维护：PURE1028。**

## 🧭 处理流程

```mermaid
flowchart TD
    A[上传 PDF / TXT / MD] --> B[读取文字与重复文件检查]
    B --> C[大模型提取简历信息]
    C --> D[保存原文件与业务记录]
    C --> E[生成向量并建立索引]
    F[输入自然语言岗位需求] --> G[创建后台任务 / 检查可复用结果]
    G --> H[解析岗位条件]
    H --> I[语义检索召回]
    E --> I
    I --> J[条件对照与差距提示]
    J --> K[多维评分与排序]
    K --> L[生成候选人分析]
    L --> M[保存结果、历史与用量]
    M --> N[工作台查看 / JSON 导出]
```

系统采用围绕招聘任务编排的处理流程：模型负责理解与分析，程序负责检索、过滤、评分、任务状态与文件管理。

| 维度 | 权重 |
| --- | ---: |
| 技能匹配 | 30% |
| 行业匹配 | 20% |
| 地点匹配 | 20% |
| 薪资匹配 | 10% |
| 学历匹配 | 10% |
| 标签匹配 | 10% |

<a id="使用方式"></a>

## 🖥️ 使用方式

1. **准备简历**：上传文字版 PDF、UTF-8 编码的 TXT 或 MD，等待解析完成。
2. **管理资料**：在简历库中搜索、查看文字、预览 PDF 或下载文件。
3. **描述岗位**：填写必备技能、经验、学历、工作地点和加分项，也可以使用岗位模板。
4. **发起筛选**：查看任务阶段与耗时，无需重复提交。
5. **复核结果**：浏览候选人排序、分项得分和分析报告，结合原始资料判断。
6. **保存与整理**：导出 JSON 结果；不再使用的简历可移入回收站，确认后再永久删除。

### 原件下载与文字重建版的区别

- **已保存 PDF 原件**：下载上传时的原始文件，保留照片、图表和排版。
- **TXT / MD 或未保留原件的旧记录**：导出 PDF 文字重建版，保留提取文字，不还原原始版式。
- **旧记录补存原件**：重新上传完全相同的文件，系统可通过文件指纹复用解析结果并补存原件。

### 删除与恢复

- **移入回收站**：从当前资料库及新的筛选中移除，保留恢复所需记录与向量备份。
- **恢复**：复用已保存的向量，不重新调用模型。
- **永久删除**：再次确认后清除回收站记录、索引备份和不再被其他记录引用的原文件，无法通过回收站恢复。
- **历史报告**：上述操作不会清除已有筛选报告，其中可能仍包含候选人相关内容。

<a id="模型调用与费用"></a>

## 💰 模型调用与费用

本项目通过远程 API 调用智谱模型，**本地部署不等于模型免费，也不等于简历内容完全不离开本机**。解析和分析时，相关文本会发送到配置的模型服务。

| 操作 | 是否可能产生模型费用 |
| --- | --- |
| 首次解析新简历、生成向量 | 是 |
| 发起新的岗位筛选、手动重试失败任务 | 是 |
| 命中相同文件或已完成任务的复用条件 | 对复用部分不重新调用 |
| 查看已有记录、预览或下载 PDF、导出已有结果 | 否 |
| 移入回收站、恢复、永久删除 | 否 |

模型请求即使在后续处理阶段失败，也可能已产生费用。页面统计基于服务商返回的用量，费用为配置单价下的估算，不包含赠送额度、缓存折扣等，最终以服务商账单为准。

参考单价可通过以下变量调整，单位为元／百万 Token：

```dotenv
LLM_INPUT_PRICE_PER_MILLION=0.8
LLM_OUTPUT_PRICE_PER_MILLION=2.8
EMBEDDING_PRICE_PER_MILLION=0.5
```

以上是当前配置值，后续请根据 [智谱官方定价](https://docs.bigmodel.cn/cn/guide/start/pricing) 更新。

<a id="常见问题"></a>

## ❓ 常见问题

**扫描版 PDF 能直接识别吗？**  
当前上传流程读取 PDF 中的文字层，尚未集成扫描件 OCR。请先转换为可提取文字的 PDF，或上传 TXT / MD。更换多模态模型本身不会自动让现有上传流程具备 OCR 能力。

**为什么下载的 PDF 只有文字？**  
该记录没有保存 PDF 原件，系统生成了文字重建版。旧记录可以通过重新上传完全相同的文件补存原件。

**为什么筛选需要等待？**  
筛选包含岗位理解、检索、评分与候选人分析。耗时取决于网络、模型服务及候选人数量；可通过进度和历史记录查看状态，避免连续重复提交。

**服务重启后数据会丢失吗？**  
业务记录、原件和向量索引保存到本地目录。重启不会主动清空数据；未完成任务会标记为中断，不自动重新调用模型。

**可以直接部署给多人使用吗？**  
当前版本未提供账号体系、权限隔离和完整的公网部署配置，适合本机体验与项目演示。多人使用需要进一步完善相关能力。

<a id="数据管理与公开仓库说明"></a>

## 🔐 数据管理与公开仓库说明

上传 GitHub 时应提交源代码、配置模板和脱敏示例，不要提交 `.env`、真实简历、SQLite 数据库、向量索引、缓存、日志及含个人信息的截图。`.gitignore` 已忽略常见运行数据，但仍需在首次提交前检查待提交文件；已被 Git 跟踪的文件不会因新增忽略规则而自动移除。

本地备份建议先停止服务，再备份 `data/`、`chroma_db/`、`cache/` 和 `.env`，以保持业务记录、原件与索引一致。
