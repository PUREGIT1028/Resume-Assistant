# 拾才 · 项目概览

## 一句话介绍

基于 FastAPI、LangChain 与向量检索的简历筛选 Agent 工作台，支持简历管理、自然语言岗位匹配、候选人报告和历史结果查看。

## 解决的问题

简历资料分散、岗位条件描述不统一、逐份查看重复劳动较多。拾才将上传、结构化提取、匹配、报告和资料管理串联为可重复运行的处理流程，供人工初筛和项目演示使用。

## 基础与定制边界

| 类别 | 内容 |
| --- | --- |
| 原项目基础 | 文档解析、模型提取、向量检索、条件检查、加权评分、排序与候选人分析；ChromaDB / Milvus 后端实现 |
| 本版本完善 | 定制工作台、后台任务、业务持久化、历史记录、请求复用、用量记录、原件管理、回收站、宽松匹配与失败后的本地规则报告 |
| 当前未实现 | 扫描件 OCR、多用户权限、公网部署方案、招聘质量基准评测 |

## 实现亮点

- **任务可追踪**：后台处理与页面轮询分离，历史记录保存任务状态和结果。
- **减少重复调用**：文件按内容指纹识别；岗位任务指纹包含资料库与模型配置。
- **匹配可解释**：保留部分匹配者，分别展示规则分数、条件提示及报告，不将分数解释为录用概率。
- **文件可管理**：上传原件与提取文本分别保存，明确区分原始 PDF 和文字重建版。
- **失败可降级**：模型分析失败时保留候选人与分数，使用简历已有信息生成本地分析，并标明来源。

## 适合展示的技术能力

API 设计、LLM 接入、结构化数据校验、向量检索、规则评分、任务状态管理、数据持久化、异常处理与前后端联调。

## 可用于项目列表的简介

拾才是基于开源简历筛选项目二次开发的招聘辅助工作台，使用 GLM-5.3-Flash 理解简历与岗位、embedding-3 进行语义向量化，并结合多维规则评分生成候选人分析。围绕本地实际使用完善了后台任务、历史记录、去重复用、原件下载和回收站功能。

## 展示时应说明的限制

目前未提供真实招聘准确率或节省工时的量化评测，不使用“准确率提升百分之多少”等未经验证的指标。模型可能超时或产生错误，所有推荐都需要结合原始资料复核。
